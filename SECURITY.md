# Security reporting

Do not post credentials, personal information, production data or exploitable details in a public issue. Use GitHub private vulnerability reporting when it is enabled. For a private repository, use an existing private channel with the repository owner; do not make the repository public to report a problem.

Describe the affected version, impact and safe reproduction steps using synthetic data. Do not test against systems or deployments without their owner's authorisation.

See [.github/security-baseline.md](.github/security-baseline.md) for contributor practices and maintainer controls. No support lifetime or response-time guarantee is implied.
